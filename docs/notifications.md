# 通知（Web Push）

## 仕組み

```
ブラウザ ──購読──▶ push_subscriptions（端末ごとに1行）
                          │
Cron / API ──web-push──▶ 各端末の購読先 ──▶ Service Worker ──▶ 通知
```

購読は端末ごとに作られる。同じ人が複数の端末を使うなら、端末の数だけ行ができる。
購読の保存は本人のブラウザから行い、RLS で自分の行しか作れない。
送信は service role で全員分を引くため、Cron と API から行う。

## iOS の制約

**Safari のタブで開いているだけでは通知を受け取れない。**
iOS 16.4 以降、Web Push は「ホーム画面に追加」した PWA でのみ動作する。
タブのままでは `Notification` も `PushManager` も存在せず、許可を求めることすらできない。

そのため `lib/push-client.ts` は、iOS でホーム画面に追加していない状態を
`needs_install` として返し、マイページで追加の手順を案内する。

## 必要な環境変数

Vercel のプロジェクト設定に追加する。

| 変数名 | 種別 | 用途 |
|---|---|---|
| `NEXT_PUBLIC_VAPID_PUBLIC_KEY` | Config | ブラウザが購読するときに使う公開鍵 |
| `VAPID_PRIVATE_KEY` | Secret | 送信時の署名。**`NEXT_PUBLIC_` を付けない** |
| `VAPID_SUBJECT` | Config（任意） | 送信元の連絡先。未設定なら本番URLを使う |

鍵の組は `npx web-push generate-vapid-keys` で作れる。
入れ替えると、既存の購読はすべて無効になる（各端末で登録し直しが必要）。

`SUPABASE_SERVICE_ROLE_KEY` は NPB 取得の Cron と共用する。

## 送るきっかけ

| きっかけ | どこから | 条件 |
|---|---|---|
| 試合の取り込み | `/api/cron/npb-sync` | 日本時間の前日に終了した試合があるとき |
| 月末の確定・入金 | 同上 | 日本時間で月の最終日 |
| 割り勘の追加 | 登録した人のブラウザ →`/api/push/notify` | その割り勘に入っている接続相手へ |
| 接続のリクエスト・承認 | 操作した人のブラウザ → 同上 | 相手へ |

割り勘と接続は、DB のトリガーではなく操作した側から呼ぶ。
そのためだけに `pg_net` を入れて鍵を持たせるより、
すでに認証のある経路に乗せる方が単純で追いやすい。

## `/api/push/notify` の約束

呼び出し側から受け取るのは「種類」と「誰に」だけ。
**本文はサーバーで組み立てる**（`lib/notifications.ts`）。
相手の画面に出る文字列を、呼び出し側が自由に決められるようにしない。

送り先は、自分と接続が成立している相手に限る。
絞り込みの条件を信用しきらず、取得した行が本当に両者のものかを
サーバー側で確かめてから送る。

接続のリクエストだけは、まだ承認されていなくても送る。
それ以外は成立している接続に限る。

## 無効になった購読

端末でアプリを消す、ブラウザが購読を作り直す、などで購読先は黙って無効になる。
送信時に 404 / 410 が返ったものはその場で削除する。
放っておくと毎回失敗し続けるため。

## 動作確認

1. ホーム画面に追加したアイコンから開く（iPhone の場合）
2. マイページ →「お知らせ」→「通知を受け取る」
3. 「テスト通知を送る」で自分あてに1通送る

届かないときは、`push_subscriptions` に行があるか、
Vercel の環境変数が入っているかを順に見る。
